The menu bar

It shows the tool you're actually using.

A bare percentage doesn't tell you which tool it belongs to. TokenWatch shows whichever tool you used most recently, its session usage, and whether its prompt cache is still warm. You can also pin exactly the numbers you care about.

Claude 22%

Follows you

The default. Shows the provider you used in the last 24 hours, with its session percent. The ring turns green while the cache is warm and blue once it goes cold. Hover it to see which project it means.

Pin what matters

Star up to two metrics per provider from any right-click menu or from Customize. The menu bar then shows exactly those, one segment per provider.

Set the Bars icon style to get a compact glyph that shows how full up to four starred metrics are, without taking much menu bar space.

Warns you when it's close

No recent activity? The icon shows whichever enabled provider is closest to its limit, colored green, orange, or red, so you see a limit coming before you hit it.

Dashboard · Limits tab

See whether you'll run out, not just how much you've used.

Every enabled provider's limits in one scrolling list. Bar color is based on your pace, so 64% used can be fine or a problem depending on how much of the window is left.

  • ▸

    Pace-aware colors

    Blue means you'll finish the window with room to spare. Orange means you'll land close to the limit. Red means you're on course to run out before it resets, and the note tells you when.

  • │

    A "now" marker on every bar

    A tick shows how far through the window you are. If the fill is past the tick, you're using it faster than the window allows.

  • ⇆

    Switch the view with one click

    Click a headline to switch every metric between % used and % left. Click a reset label to switch between a countdown and the exact reset time.

  • ☷

    All your Claude & Codex accounts

    A second Claude or Codex profile on this Mac shows up as its own card with its own limits. You don't need to switch accounts to check it.

  • ⇅

    Arrange it your way

    Drag a provider's header to reorder. Right-click to star, hide, refresh, or copy a PNG screenshot of the card to the clipboard. Data from more than two refreshes ago is marked Outdated.

Dashboard · Usage tab

See what you spent, and what's about to cost more.

The Usage tab adds up spend from your local session logs. You don't need an admin API key and nothing is uploaded.

  • ◐

    Total Spend

    A donut in each provider's brand color. Show it as Cost, Cost per MTok, or Tokens for Today, Yesterday, or 30 Days. Hover the center for the exact figure, or hover a provider to see what each model cost.

  • ≡

    Spend by model

    Each provider card shows today's and yesterday's spend. Expand it to see each model's cost and share.

  • Every active session's cache

    One row for each Claude Code or Codex session you used in the last 5 hours. Each row shows the project, a flame or snowflake, and the cache hit rate.

  • ▁

    7-day history

    Daily cost or tokens for the last week, priced at API list rates. The rates refresh against a public price list and also work offline.

Warm cache: cheap

Claude keeps your conversation cached after each message, for either 1 hour or 5 minutes depending on the session. TokenWatch reads which one each session uses from its log. Send your next message in that time and the context is read from cache at a fraction of the price.

api-gateway100% hit · expires 14:06

Cold cache: full price

Once that time passes, the cache expires and your next message pays full price to re-read the whole context. TokenWatch shows how many tokens that will be before you send.

mobile-appcold · re-reads ~412.8K tok

ⓘ Codex

Codex gets the same warm/cold indicator from its local logs. It shows whether the last turn hit the cache but no expiry time, because OpenAI keeps cache timing on its servers and doesn't expose it.

Customize & settings

Set it up once and leave it running.

Dashboard, Customize, and Settings are three screens in the same popover. It resizes to fit what's on screen, and you can do everything from the keyboard.

☰

Customize

Turn providers on or off and drag to reorder them. For each provider, drag metrics between Always Visible and On Demand, or star up to two for the menu bar. ⌘Z undoes any change.

Alerts before you hit a limit

Three native notifications, each off by default:

  • Almost Out: under 10% left
  • Cutting It Close: on pace to land near the limit
  • Will Run Out: on pace to run out before reset

Each alert fires once when a limit crosses into that state, not on every refresh.

◑

Appearance

  • Theme: System, Light, or Dark
  • Density: Default or Compact
  • Icon style: Text or Bars
  • 12- or 24-hour reset times
  • Reduce Animations and Increase Transparency

Hide from screen share

Keeps the popover out of screen recordings and screen shares, so your spend doesn't show up in a demo or on a call.

⌘

Global shortcut

Record any key combination to open TokenWatch from any app. It doesn't need Input Monitoring permission.

↻

Refresh when you want

Refreshes every 5 minutes by default, and you can set it anywhere from 1 to 30 minutes. The footer counts down to the next refresh; click it or press ⌘R to refresh now. You can also turn on Launch at Login.

Get started

Set up in about a minute.

No account and no sign-up. Install it, turn on the providers you use, and it starts working with the sign-ins already on your Mac.

Install

Install with Homebrew, or download the signed and notarized DMG and drag it into Applications.

brew install --cask MetaPouch/tokenwatch/tokenwatch

Launch

TokenWatch runs only in the menu bar, with no Dock icon. The first time, it opens the dashboard for you so you can find it.

Turn on your providers

Open Settings from the ⋯ menu or with ⌘,. Turn on the tools you're already signed in to. For providers that use an API key, paste it in the field next to the toggle.

Make it yours

Press ↩ to open Customize. Reorder providers, hide metrics you don't need, and star the ones you want in the menu bar. Turn on alerts in Settings.

Updating

TokenWatch doesn't check for updates in the background, so nothing phones home. With Homebrew, run the upgrade command. If you installed the DMG, download the latest release and drag it over the old copy.

brew update && brew upgrade --cask tokenwatch

Privacy

Your usage data stays on your Mac.

No TokenWatch server, no telemetry, no analytics SDK, and no account. It makes two kinds of network requests, and nothing else.

  • Keys in the Keychain

    API keys you paste are stored in the macOS Keychain, not in a config file.

  • ☉

    Local notifications

    Alerts are delivered by macOS on your Mac. Nothing about them is sent anywhere.

  • ◇

    Open source

    The code is written from scratch in Swift and MIT licensed. You can read it, check every network call, and build it yourself. SECURITY.md lists everything it reads and why.

FAQ

Questions

Is it really free?

Yes. It's MIT licensed with no paid tier, no account, and no ads. The full source is on GitHub.

Are the spend figures what I'll actually be billed?

They're estimates. TokenWatch prices your local session tokens at each model's API list rate. If you're on a subscription like Claude Max, you aren't billed per token, so treat the numbers as "what this would cost on the API." It's still a good way to see which models and projects use the most.

Why does it need macOS 26 Tahoe?

The popover is built on Liquid Glass, which requires the macOS 26 SDK.

Can I see more than one Claude or Codex account?

Yes. If you have a second profile on this Mac (a separate CLAUDE_CONFIG_DIR or CODEX_HOME), it shows up on the Limits tab as its own card. TokenWatch only reads these accounts. It never changes which account your CLI uses.

Why doesn't it update itself?

An auto-updater would contact a server in the background, and TokenWatch doesn't do that. The Homebrew cask also sets auto_updates false. To update, run brew upgrade --cask tokenwatch or download the latest DMG.

Does it read my prompts or code?

It reads your local session log files, but only uses token counts, timestamps, model names, and project folder names from them. Nothing from those logs is ever sent anywhere.

How do I uninstall it completely?

Run brew uninstall --zap --cask tokenwatch. This also removes its settings, caches, and preferences. For a DMG install, drag the app to the Trash and delete ~/Library/Application Support/TokenWatch.

My provider isn't listed. Can I add it?

Yes. Each provider is one self-contained Swift file plus a test fixture. CONTRIBUTING.md explains how to add one, or you can open an issue to request it.
